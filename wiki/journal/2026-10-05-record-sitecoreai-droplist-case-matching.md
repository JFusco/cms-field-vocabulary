# Record SitecoreAI Droplist case matching

The October 2-4 daily `sitecore-ai.changelog-index` scans reported fingerprint `e58844310302d74ba5d6226c8db597fb621601551213e693bdbf02222f66fdde`. The added [SitecoreAI base image 1.10.13 release note](https://developers.sitecore.com/changelog/sitecoreai/29092026/sitecoreai-base-image-release-1.10.13) says, under resolved issues, that Droplist selected-value comparison is now case insensitive and the selected item displays correctly in the UI. The October 2 [scan artifact](https://github.com/JFusco/cms-field-vocabulary/actions/runs/37047273279) contains the index identity and summary.

The `sitecore-ai.authoring.current` profile previously held `Droplist` as a native-token-only entry. A supplemental editor source, `sitecore-ai.droplist-case-insensitive`, now supports an `editorBehavior` claim at locator `Resolved issues > Droplist selected value comparison`. Its new lock fingerprint is a proposal in the draft PR for maintainer approval. The generated catalog and authoring documentation reflect the behavior. The profile retains its native field identity; Content SDK value and delivery shapes and consumer routing are unchanged.
