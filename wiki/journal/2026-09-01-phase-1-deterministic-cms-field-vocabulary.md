# Phase 1 deterministic CMS field vocabulary

Phase 1 establishes `cms-field-vocabulary` as the official-source-backed authority for CMS field identities, semantics, and deterministic coding-agent rendering contracts.

## Why

Adapter prose had begun to carry platform field vocabularies and rendering implications directly. That duplicates vendor semantics, makes updates uneven across consumers, and spends agent context on inactive platforms. The package instead keeps evidence and human documentation at the source while projecting only the selected adapter and exact referenced fields as structured operations.

## Delivered so far

- Human-authored profile records preserve official native tokens, claim evidence, applicability, and extensibility boundaries.
- Rendering implications use a closed operation and prohibition vocabulary with explicit authority channels.
- Consumer projection is exact-adapter, exact-profile, digest-bound, deterministic, and intentionally separate from future AI Orchestration and COS integration.
- Official-source review and freshness automation retain approved snapshots and report drift without mutating vocabulary.
- Repository hooks, shared GitHub workflows, packed-consumer verification, and Semantic Release configuration are present.
- Sixteen isolated profiles currently compile 263 exact native facts from 52 reviewed official sources. The final audit separated Optimizely CMS 13 admin labels from .NET model types and Sitecore authoring vocabularies from SDK delivery contracts.
- Freshness schema v2 independently discovers the complete token set for every exhaustive enumeration source. WordPress Core 7.1 is anchored to the exact Core commit and Gutenberg handbook revision while the mandated rolling documentation URLs remain supplemental evidence.
- A final live review reached all 52 official sources with no enumeration, claim, version, removal, or reachability drift. Raw-only vendor page churn remains classified and retained in scan artifacts without creating source-issue noise.
- Runtime contracts now detach all public lookup results, expose the canonical singleton and rendering definitions as deeply readonly, require exact rendering-branch selections, emit no CMS-free artifact, and keep COS on a compact official-data projection without agent rendering policy.
- Named selected-contract fixtures now carry exact byte and deterministic token-estimate ratchets, including both link and media branches for Optimizely SaaS content references.

Current path evidence includes `package.json`, `definitions/rendering-operations.json`, `sources/official-sources.json`, and `.github/workflows/release.yml`.
